## 初步解决方案

当前项目应继续保持 MPD 主流程和 IsaacLab 仿真验证分离：MPD 环境负责数据、训练、推理、轨迹优化；IsaacLab 环境只负责把 MPD 已生成的 Panda joint-space 轨迹放进物理仿真里 replay，并返回碰撞统计。不要把 IsaacLab 直接并入 MPD 主环境，也不要为了 IsaacLab 改模型或数据集格式。

### 1. IsaacLab 非 headless 没有实际画面、最后窗口卡住

当前 `--isaaclab_headless False` 只表示 IsaacLab/Isaac Sim 子进程允许渲染窗口；它不是一个完整的交互式 replay viewer。现在的 `scripts/isaaclab/evaluate_mpd_trajectories.py` 主要目标是批量验证轨迹碰撞，跑完后写 `isaaclab-statistics-XXX.json`，不是给人持续观看的 GUI。因此可能出现窗口打开但没有合适视角、画面不明显，或者统计写完后 Isaac Sim 关闭阶段卡住。



- 新增一个专门的 IsaacLab replay 脚本，例如 `scripts/isaaclab/replay_mpd_trajectory.py`，不要复用批量 evaluator。
- replay 脚本只加载 1 条或少量轨迹，降低 `num_envs`，慢速逐帧执行，固定相机视角。
- replay 脚本可以在结束后等待用户关闭窗口，不走当前 evaluator 的自动终止逻辑。
- inference 主流程继续使用当前 evaluator，避免 GUI 卡住影响批量实验。



### 3. Warehouse Panda 配置的 IsaacLab 验证还不完整

`config_EnvWarehouse-RobotPanda-config_file_v01_00.yaml` 对应 Warehouse 配置文件环境 + Panda。MPD 推理可以按该 cfg 生成 Panda joint-space 轨迹，但当前 IsaacLab evaluator 主要稳定支持 Panda 关节轨迹 replay；障碍物场景还没有从 MPD/PyBullet 环境完整导出到 IsaacLab。因此如果直接用 IsaacLab 验证 Warehouse，可能只验证了 Panda 运动本身，没有严格验证 Warehouse 障碍物碰撞。



1. 先定义 MPD 到 IsaacLab 的场景导出 contract。

建议在 `isaaclab-trajectories-XXX.pt` 里增加或并行写一个 scene payload：

```python
{
    "q_trajs_pos": ...,        # [H, B, 7]
    "q_pos_starts": ...,
    "q_pos_goal": ...,
    "robot_name": "panda",
    "env_name": "EnvWarehouse",
    "obstacles": [
        {"type": "box", "name": "...", "pose": [...], "size": [...]},
        {"type": "sphere", "name": "...", "pose": [...], "radius": ...}
    ]
}
```

2. 在 IsaacLab evaluator 里根据 payload spawn 静态障碍物。

- box/cuboid 映射到 IsaacLab `CuboidCfg` 或等价静态 collider。
- sphere 映射到 IsaacLab `SphereCfg` 或等价静态 collider。
- 障碍物 pose、尺寸、坐标系必须和 MPD/PyBullet 环境对齐。

3. 接触检测仍保持当前返回格式。

继续写：

```json
{
  "backend": "isaaclab",
  "env_name": "EnvWarehouse",
  "n_trajectories_collision": 0,
  "n_trajectories_free": 64,
  "n_trajectories_free_fraction": 1.0,
  "collision_mask": [...],
  "first_collision_step": [...]
}
```

4. 先做 EnvSpheres3D，再做 Warehouse。

EnvSpheres3D 障碍物简单，更适合作为 IsaacLab obstacle export 的第一步；Warehouse 通常包含配置文件里的多 box/复杂布局，应在 sphere 场景对齐后再迁移。

### 推荐优先级

1. 保持当前 headless IsaacLab evaluator 稳定，确保 Panda + EnvSpheres3D 能批量返回统计。
2. 在非支持环境上加 warning/NotImplementedError，避免 Warehouse 结果被误读。
3. 实现场景 obstacle export，先支持 sphere，再支持 Warehouse box。
4. 最后实现 IsaacLab 视频录制和单轨迹 GUI replay。
