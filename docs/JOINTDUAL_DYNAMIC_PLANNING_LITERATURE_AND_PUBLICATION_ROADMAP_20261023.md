# JointDual 动态规划研究路线：近期文献、投稿定位与实验方案

调研日期：2026-10-23。代码核对基线：本仓库当前工作区，HEAD `14abe51`。本文只新增研究文档，不修改规划、训练或运行时实现。

研究对象是以下两条路线：

- **路线 A：预测闭环。** 根据观测预测障碍运动并膨胀障碍，持续重规划，通过候选评分选择轨迹，再用多项式 handoff 接续执行。
- **路线 B：确定性时空规划。** 给所有算法相同的障碍未来轨迹，在一次规划请求内生成完整可执行轨迹，与 ST-RRT*、SI-RRT 等方法比较。

本文将“文献事实”“代码事实”和“研究建议”分别说明。关于投稿潜力的判断是研究定位分析，不代表已经取得性能优势或可以保证录用。

## 1. 建议先做什么

**以当前 JointDual、仿真优先的阶段，建议采用 B 作为论文主线，A 作为后续闭环扩展。**

原因是 B 能直接检验 JointDual 最有价值的假设：在动态障碍条件下，联合学习几何路径与执行时间，是否比先生成路径、再调整时间，更容易在有限计算预算内获得高质量可行解。

A 按目前描述可以成为有用的工程系统，但预测、膨胀、候选排序、滚动规划和多项式接续都已有较多研究或成熟实现。把它们组合起来，需要大量系统调试，却不一定产生同等强度的方法贡献。如果希望 A 成为论文主线，应进一步研究预测误差、规划延迟、切换约束或失效恢复中的一个核心问题。

两条路线不是互斥算法。可以使用同一个 JointDual 规划核心：先以准确世界轨迹作为输入，测量规划能力；再以在线预测替换输入，测量不确定性和闭环执行造成的性能损失。

| 判断维度 | A：目前描述的闭环方案 | B：确定性时空联合规划 |
|---|---|---|
| 与现有 JointDual 的距离 | 还需运动边界、时间同步、切换与恢复 | 已有 oracle world 和单次推理入口可复用 |
| 新增工程量 | 较大，跨预测、规划、执行多个模块 | 相对集中在算法与 benchmark |
| 当前方案的方法创新 | 容易被视为已有组件集成 | 需要证明联合建模优于分离建模 |
| 结果归因 | 很容易受到膨胀、频率、控制误差影响 | 更容易隔离先验、context 和 guidance 的收益 |
| 主要研究空间 | 风险、延迟、接管可行性、计算复用 | 时空耦合、多模态、可行率、解质量 |
| 首篇工作的投入产出 | 当前版本偏低；提出新机制后可以提高 | 当前阶段更有利 |
| 真机迁移方式 | 直接面向观测驱动的动态系统 | 可先使用受控移动障碍或已知轨迹的另一机械臂 |

## 2. 问题定义：避免混淆三个“时间”

### 2.1 几何路径、物理时间与扩散步数

设机器人关节轨迹为：

\[
q(t)=Q(s(t);P),\qquad s\in[0,1],\quad t\in[0,T].
\]

其中 `P` 决定空间路径，`s(t)` 决定沿路径的执行进度，`T` 是总执行时长。扩散模型中的去噪步数 `k` 是另一个概念，与物理执行时间 `t` 不同。

需要区分：

1. **固定物理时间网格的轨迹生成**：生成 `q(t_0), ..., q(t_N)`，各点时间预先固定。
2. **空间生成后重新定时**：先确定 `Q(s)`，再优化 `s(t)`，空间路径不会因新的时间窗口而重新选择。
3. **空间—时间联合生成**：路径参数和时间参数一起生成，且在物理约束或碰撞 guidance 中相互影响。

模型具有 temporal attention、diffusion timestep embedding 或未来障碍 token，并不自动意味着实现了第三类。

### 2.2 路线 B 需要的是障碍时序轨迹

每个障碍需要提供：

\[
O_i(t)=\{\text{shape}_i,\text{size}_i,p_i(t),R_i(t)\}.
\]

仅知道障碍经过哪些位置，不知道何时到达，不能构成确定性的时空碰撞问题。当前实现对障碍方向有额外限制，不能把上式的一般刚体运动能力直接归于现有代码。

规划任务还应明确：起始状态、目标集合、速度和加速度限制、规划起始世界时刻、最大规划时间窗、到达后的占位规则。

当前 JointDual 以末端位姿作为目标条件，更准确的任务形式是：

\[
q(0)=q_s,\qquad FK(q(T))\in\mathcal G_{EE}.
\]

这里的目标集合可能包含不同的逆运动学解。它与强制 `q(T)=q_g` 的固定关节终点任务不同。

### 2.3 “单次 plan”不等于一次网络前向

路线 B 可以使用多步扩散、多候选采样、梯度修正和最终验证。单次规划表示执行期间不再根据新观测替换轨迹，整个求解过程计入一次请求预算。

路线 A 在每轮得到新的预测 `O_hat_i(t | y_0:k)`，并反复调用规划核心。预测层和调用频率属于闭环系统设计，不应与规划核心本身的能力混为一谈。

## 3. 检索范围与证据使用

本次采用面向选题的定向检索，重点覆盖 2024—2026 年的动态机械臂规划、扩散轨迹生成、时空搜索与不确定性闭环规划，并补充 ST-RRT* 等必要基础工作。

检索关键词包括 `dynamic obstacle diffusion motion planning`、`space-time diffusion duration`、`safe interval manipulator`、`uncertainty adaptive replanning diffusion`、`time allocation motion planning`。优先使用论文原文、正式会议论文集和作者项目页面。

本文选取 11 项相关工作进行比较，不构成系统性综述或穷尽式新颖性检索。不能仅因这些论文没有覆盖某项设计，就宣称该设计是首次提出。不同论文的机器人、碰撞模型、硬件与成功标准不同，因此不直接横向拼接其成功率和毫秒数。

## 4. 相关文献及其对 JointDual 的影响

### 4.1 ST-RRT*：已知动态环境下的基础对照

**文献事实。** ST-RRT* 面向动态障碍、速度约束及未知到达时间，在空间—时间中进行双向搜索；论文给出相应假设下的概率完备性与最短到达时间渐近最优性，并包含 7 自由度机械臂实验。发表于 ICRA 2022。[R1：论文](https://arxiv.org/abs/2203.02176)

**对本项目的影响。** 已知障碍未来轨迹是成立的研究设定，并非把动态问题变成静态问题。JointDual 更适合主张有限预算下的可行解产出与质量，而不是直接声称取代搜索算法的理论性质。

**比较边界。** 原始时空搜索解与满足加速度、平滑性及执行接口要求的轨迹之间可能需要后处理。必须分别记录原始解和最终可执行解，不能把不同输出标准混在同一个成功率里。

### 4.2 SI-RRT：不能遗漏的近期机械臂动态规划基线

**文献事实。** SI-RRT 将 safe interval 思想与 RRT-Connect 结合，用于动态障碍下的高自由度机械臂规划，并提供公开实现。正式发表于 ICAPS 2025。[R2：正式论文页](https://ojs.aaai.org/index.php/ICAPS/article/view/36120)；[作者代码](https://github.com/PathPlanning/ManipulationPlanning-SI-RRT)

**对本项目的影响。** 只比较 ST-RRT* 容易遗漏更近期且针对相近问题的搜索方法。建议将 SI-RRT 纳入主基线，核对障碍运动表示、目标定义和等待动作处理后再做数值比较。

**比较边界。** 不把该工作与名称相近的多移动机器人 SI-RRT* 混用；论文中的相对优势也不能直接视作在本仓库场景中必然成立。

### 4.3 MPD：联合执行时间的直接研究起点

**文献事实。** MPD 使用低维 B-spline 轨迹表示、扩散先验及代价引导。所核对的 2025 版本明确说明实验未优化任务总时长，将其留作后续工作。[R3：MPD](https://arxiv.org/html/2412.19948v2)

**对本项目的影响。** 从固定时长轨迹生成扩展到可变时间分配和动态碰撞，是相对原 MPD 清晰的研究方向。论文需要证明这种扩展带来算法收益，不能只证明程序可以输出不同 duration。

**比较边界。** 与旧 checkpoint 比较时要区分训练数据、轨迹表示、目标条件的变化。最重要的因果对照应在相同新数据和表示上训练，而不是只对比旧模型。

### 4.4 CAMPD：障碍 context 本身已不是充分创新

**文献事实。** CAMPD 使用结构化、与传感器类型无关的环境条件，通过注意力支持不同数量的上下文元素；作者项目页标注 ICRA 2026，并报告 7 自由度机械臂及未见环境实验。[R4：作者项目页](https://meco-group.github.io/campd/)；[论文](https://arxiv.org/abs/2510.14615)

**对本项目的影响。** 障碍 token、可变障碍数量、attention 和环境条件化都需要与既有方法区分。JointDual 的重点应是物理时间与路径选择如何共同受世界信息影响。

**比较边界。** 不能根据项目页中的动态应用描述，就认定它已经解决任意未来障碍轨迹下的联合时长生成；相关能力需以具体方法与实验为准。

### 4.5 动态障碍条件下的机械臂扩散规划：最接近的近期工作

**文献事实。** 2026-10-22 发表的 *Diffusion-Guided Trajectory Priors for Efficient Robotic Manipulator Motion Planning in Dynamic Environments* 采用粗到细扩散生成、未来障碍状态的时空 cross-attention、局部 guidance 和 ST-CHOMP 修正，并包含反应式重规划。其公式使用固定 waypoint 物理时间步长 `Δt=0.15 s`。[R5：出版社原文](https://www.mdpi.com/2218-6581/15/11/211)

**对本项目的影响。** “未来障碍输入＋扩散规划＋后优化＋replan”已经存在直接相关工作，不能作为宽泛的首创主张。可重点比较其固定时间网格与 JointDual 联合生成路径、时间形状和总时长的差异。

**比较边界。** 本文没有复现该工作的数值结果，不把其表格作为本项目性能参照。需要进一步核对不同轨迹分辨率的时间对应、完整流水线耗时和评价协议，才能决定是否能直接复现为基线。

### 4.6 MMD：扩散先验与时空约束搜索的结合

**文献事实。** MMD 将单机器人扩散模型与经典搜索结合，用单机器人数据处理多机器人轨迹协调，并研究多个模型的组合。发表于 ICLR 2025。[R6：论文](https://arxiv.org/abs/2410.03072)；[作者项目](https://multi-robot-diffusion.github.io/)

**对本项目的影响。** 可以考虑将 JointDual 用作满足时空约束的候选生成器，未来接入优先级规划或冲突消解；这也提示“扩散＋经典规划”本身不是新贡献。

**比较边界。** 多机器人协调与单机械臂面对外生动态障碍的任务范围不同。首轮不必为了扩大范围，立即实现多机械臂联合规划。

### 4.7 SMD：可行性处理也需要明确创新边界

**文献事实。** *Simultaneous Multi-Robot Motion Planning with Projected Diffusion Models* 在扩散采样中结合约束优化，处理多机器人碰撞与运动学可行性，并提供 benchmark。发表于 ICML 2025。[R7：正式论文页](https://proceedings.mlr.press/v267/liang25e.html)

**对本项目的影响。** 若后续采用投影或约束修正，需要说明它针对本项目的路径—时间耦合解决了什么具体问题。仅将 soft cost 换成 projection，不足以自动形成独立创新。

**比较边界。** 可以参考其约束处理和实验组织，但不应直接引用其任务中的成功率来评价 JointDual。

### 4.8 扩散路径生成后做时间协调：直接支持设置分离基线

**文献事实。** *MultiRobot Motion Planning Based on Diffusion and Time–Space Path Planning* 复用单机器人 MPD，以交替的碰撞引导生成多机器人轨迹，再通过 time–space A* 调整沿已有路径的执行进度、处理剩余时间冲突。出版社标注首次发表于 2026-06-30。[R8：出版社原文](https://ietresearch.onlinelibrary.wiley.com/doi/10.1049/aie2.70022)

**对本项目的影响。** “生成路径后进行时序协调”是具体而有意义的对照。JointDual 必须展示在需要同时换路径和换时间窗口的任务上，联合生成比这种分离处理更有效。

**比较边界。** 该论文的多机器人任务不必完整搬入当前单臂实验；可以在相同场景中实现概念匹配的“空间生成＋固定路径 retiming”基线，并清楚标注为本项目实现。

### 4.9 基于不确定性的扩散重规划

**文献事实。** *Dynamic Obstacle Avoidance through Uncertainty-Based Adaptive Planning with Diffusion* 根据动作预测不确定性调整重规划频率，以减少扩散模型反复生成重叠序列的计算。本文引用其 2024 年预印本版本。[R9：论文](https://arxiv.org/abs/2409.16950)

**对本项目的影响。** “不每步重规划”“根据不确定性触发扩散规划”已有相关研究。若沿 A 发展，需要进一步说明触发依据与机械臂未来接管状态、障碍风险或计算预算的关系。

**比较边界。** 动作预测不确定性与障碍状态预测协方差不是同一种量，不能把该工作概括为与 Kalman 障碍膨胀完全相同。

### 4.10 DYNUS：闭环路线需要面对的更完整研究问题

**文献事实。** DYNUS 提出时空全局规划、时间安全走廊，以及探索、安全和应急轨迹组合，并通过约束问题结构减少局部优化开销；实验覆盖无人机、轮式和四足平台。所查 arXiv 页面仍标注 T-RO 审稿中，本文按 2025 预印本引用。[R10：论文](https://arxiv.org/abs/2504.16734)

**对本项目的影响。** 单纯增加障碍膨胀和 replan 不容易形成强主张。更有价值的问题是：新计划未完成或预测突然变化时，系统仍能执行什么，以及安全与计算预算如何共同约束决策。

**比较边界。** 它是系统设计参考，不能直接用移动平台结果比较高自由度机械臂，也不能将其安全表述扩展为任意未知障碍行为下的无条件保证。

### 4.11 TVCBF：安全执行层与全局规划层应分开评价

**文献事实。** *Differentiable Optimization Based Time-Varying Control Barrier Functions for Dynamic Obstacle Avoidance* 研究动态几何障碍的时变 CBF，考虑测量噪声和执行限制，并包含 7 自由度 Franka Research 3 实验。本文引用 2024 修订版。[R11：论文](https://arxiv.org/abs/2309.17226)

**对本项目的影响。** 后续可以评估独立安全执行层对碰撞与任务完成率的影响。但局部安全控制和全局时空规划解决的问题不同，不宜把“有安全层的 JointDual”与“没有安全层的搜索规划器”直接作为算法对比。

## 5. 论文贡献应该如何定位

### 5.1 B 的建议研究问题

> 给定动态障碍的时间参数化运动，联合建模空间路径与时间参数，能否在相同在线计算预算下，提高高自由度机械臂可执行轨迹的生成效率，并保留不同通过策略？

可考虑的论文题目：

> Joint Space–Time Diffusion for Manipulator Planning with Moving Obstacles

题目中的 dynamic 表示障碍随物理时间移动，不暗示已经解决任意未知运动预测。若只在固定静态场景训练与评估，应在正文中明确适用范围。

建议围绕三个可验证贡献组织，而不是罗列模块：

| 候选贡献 | 需要证明的内容 | 不能作为充分证据的结果 |
|---|---|---|
| 空间—时间联合先验 | 同数据、同表示、同预算下优于分离模型 | 网络有两个输出 head |
| 世界条件下的时序决策 | 障碍相位变化引起合理的路径或时间变化 | 只在随机测试集上总体成功率提高 |
| 有限预算下的可执行解生成 | 验证后成功率、首解时间、执行质量形成优势 | 仅报告网络前向时间 |

### 5.2 “联合”必须具有可观察的作用

同一任务可能存在不同策略：短路径提前通过、减速后通过、在安全处等待、绕行但更早到达。空间路径决定可使用哪些通道，时间分配决定能否进入通道对应的开放窗口。

分离模型不一定失败。若多数任务只需全局减速，简单 retiming 就可能已经足够。因此 benchmark 应包含不同耦合强度，并检验 JointDual 的优势是否集中在真正需要联合选择的任务上。

建议以学习分布表达核心差别：

\[
p_\theta(P,z\mid q_s,g_{EE},W),
\]

而分离方法可以是：

\[
p_\phi(P\mid q_s,g_{EE},W)\,
p_\psi(z\mid P,q_s,g_{EE},W).
\]

两者都应允许相同的世界信息。不能让联合模型看到未来障碍，而故意不给分离基线同样的信息，再把提升全部归因于联合结构。

### 5.3 A 怎样才值得成为独立主线

目前最贴合本项目的研究问题是：

> 在存在预测误差和非忽略推理延迟时，如何生成能在未来接管时刻执行、并满足连接与风险约束的轨迹？

这比继续增加评分项更具体，也能连接非零初速度、handoff 和 JointDual 的能力。建议在下面三个方向中选一个作为核心，不同时扩张全部范围：

| 可选方向 | 方法内容 | 关键对照 |
|---|---|---|
| 延迟与接管状态联合处理 | 根据未来接管状态规划，将连接段纳入同一时空验证 | 当前状态规划＋后接多项式；相同预测和执行器 |
| 不确定性与时空策略联合处理 | 区分几何可通过性、预测可信度与风险预算 | 固定膨胀、随时间膨胀、协方差膨胀 |
| 时序一致的计算复用 | warm-start、候选模式保留、事件触发与预算分配 | 同总计算量下的从头重规划、固定频率调用 |

单独增加 hysteresis、五次多项式或 Kalman filter 通常更适合作为实现细节。方法创新应由定义明确的机制和受控实验支持。

## 6. 为什么 A 更容易消耗时间

### 6.1 成功率受到多层因素影响

一次闭环执行的结果同时受到观测质量、目标关联、运动预测、膨胀程度、规划预算、候选选择、接管时刻和控制误差影响。

例如增大膨胀可能降低碰撞，但增加无解与等待；提高 replanning 频率可能改善反应，却增加过时结果和频繁切换；放慢执行可能改善成功率，但掩盖规划质量问题。

因此必须将碰撞率、完成率、超时率、急停率和完成时间分开报告。机器人停住且没碰撞，不等于任务成功。

### 6.2 多项式 handoff 的保证范围有限

五次多项式可用于匹配连接两端的位置、速度和加速度。满足这些端点条件并不意味着连接过程中无碰撞、不超过速度或加速度限制，也不意味着新轨迹在实际接管时间仍然有效。

闭环验证对象应是“剩余承诺轨迹＋连接段＋新轨迹＋必要的终端保持”，并使用对应的绝对物理时刻。只验证新轨迹主体会漏掉最容易出问题的连接阶段。

### 6.3 膨胀不是天然的概率保证

障碍均值预测、协方差传播和几何膨胀是三个不同步骤。固定 margin、随预测时间增长的 margin、协方差相关 margin 都可以作为工程策略，但需要说明其假设与参数来源。

若要主张概率约束，需要定义整个执行区间的碰撞事件，例如：

\[
\Pr\left[\exists i,\exists t\in[0,T]:
\operatorname{dist}(Robot(q(t)),O_i(t))<0\right]\le\delta.
\]

某个障碍在某个采样时刻的置信椭球，并不直接给出上式。跨时间、跨障碍的风险组合、预测校准以及采样间隔内的碰撞都需要单独处理。这是可研究的问题，不是当前膨胀实现已经具备的保证。

### 7.1 非零初速度是否必须先做

对 B 的首轮实验，不必。可以先做静止起终点、单次规划，集中验证空间—时间联合生成。

对 A，未来接管状态通常具有非零速度，必须明确边界处理。实现边界支持也不等于一定要立刻增加速度条件并重训：可以先研究保留现有先验、在解码和约束处理中施加运动边界，测量其可行率，再决定是否微调或重训。

需要注意，若路径端点控制点随执行时长变化，按旧静止路径计算的 `T_min` 不能自动作为新轨迹满足速度、加速度约束的保证。`tau_r` 的表示和有效性检查需一起审视，不能只修改请求校验。

### 7.2 ToDrawer 是否应成为首个主场景

不建议在尚未测清 Warehouse 内算法质量时，同时引入静态环境迁移。更省时间的顺序是：Warehouse 内形成严格实验，再加入 ToDrawer 作为扩展场景。

如果直接使用 Warehouse checkpoint 到 ToDrawer，应标明静态场景分布迁移；如果在 ToDrawer 重训或微调，应报告额外数据与训练成本。动态 world context 并不自动提供对静态柜体几何的条件化能力。

## 8. 路线 B 的 benchmark 设计

### 8.1 主协议：固定问题，再运行算法

建议每个场景保存以下信息，形成冻结的数据清单：

| 类别 | 建议字段 |
|---|---|
| 身份与复现 | `scenario_id`、生成版本、seed、配置 hash、family/group id |
| 机器人与静态场景 | robot hash、几何 hash、坐标系、碰撞表示 |
| 任务 | 起始 q/dq/ddq、目标类型与集合、目标误差容限 |
| 世界时间 | `world_t0`、预测覆盖区间、执行期限、目标保持时长 |
| 动态障碍 | 几何类型、尺寸、完整时间序列或可复算运动函数 |
| 难度标签 | 数量、速度、相位、通道、交互窗口宽度、生成机制 |
| 生成审计 | 初始合法性、静态重叠情况、参考轨迹交互情况 |
| 参考求解 | solver/version/budget、结果状态、后处理结果 |

**保存实际世界实例，而不只保存采样范围和随机种子。** 依赖版本、浮点行为和拒绝采样规则变化都可能使相同 seed 生成不同世界。

### 8.2 沿参考轨迹放置障碍：可以使用，但要控制偏差

建议流程：

1. 为静态场景生成多条参考路径，而不是每个起终任务只使用一条路径。
2. 从移动连杆的 swept region 选择潜在交互位置，避免仅围绕末端布障。
3. 采样障碍形状、尺寸、速度、相位和运动模式，冻结完整世界。
4. 用统一预检规则排除明确不合法的初始状态等情况，记录全部拒绝原因。
5. 使用一个或多个参考求解器进行可解性审计，保存超时和失败记录。
6. 在独立世界中运行各算法，不根据某个待比较算法的结果重新采样。

参考路径只是让场景具有交互意义，不应强制最终解经过同一条路径，也不应成为规划器可见的额外信息，除非所有算法都获得同等信息。

### 8.3 不要把 teacher 未求解等同于场景不可行

建议同时报告：

- **满足预定义场景合法性规则的全部测试集**：保留参考求解失败的场景。
- **参考求解器获得有效解的子集**：用于可解性已知条件下的分析。

后者不能替代前者，也不能无条件代表一般任务分布。若训练只包含 teacher 成功轨迹，测试更应记录这种数据选择带来的适用边界。

当前 multiworld 生成中还存在与事件时刻相关的到达下界，以及要求事件落在执行窗口内部的审计规则。它们有利于生成交互样本，但可能排除提前完成的有效策略，不宜原样作为评价算法的规则。依据：[multiworld 生成器](../scripts/spacetime_data/generate_warehouse_multiworld.py)、[world 与 interaction audit](../scripts/spacetime_data/warehouse_world.py)。

### 8.4 场景应覆盖不同耦合强度

| 场景组 | 目的 | 预期能区分什么 |
|---|---|---|
| 空 world／无关障碍 | 检查是否无故绕路或延迟 | 先验是否过度保守 |
| 单次横穿、宽时间窗口 | 基础动态避障 | 固定路径 retiming 是否已足够 |
| 狭窄时间窗口 | 对实际通过时刻敏感 | timing 精度与 guidance 作用 |
| 多次占据同一通道 | 多个 before/after 选择 | 时间模式覆盖 |
| 不同通道对应不同开放时间 | 路径和时间必须共同选择 | 联合模型相对分离模型的收益 |
| 提前完成优于等待 | 允许机器人在后续事件前结束 | 是否学到了“等所有障碍结束”的偏差 |
| 短暂停留、反向或分段变速 | 恒速假设失效或弱化 | B 的表示能力与 A 的预测损失 |
| 起始位置附近出现障碍 | 暴露等待和首轮计算的影响 | 在线启动与离线求解的差别 |

数量、速度和尺寸应分层采样，避免“更多障碍”同时意味着更慢运动或更宽通道。具体范围应来自机器人工作空间、执行限制与试验校准，不直接照搬其他论文的数值。

### 8.5 训练／验证／测试拆分

按参考路径家族、起终任务家族和世界派生关系分组拆分。相同参考路径只换障碍相位的近重复样本，不应跨 train/test。

主实验首先报告分布内表现，然后分别增加障碍数量、速度、运动模式和静态场景迁移。不要把所有变化混成一个 OOD 集后，只报告平均值。

建议另建一组严格配对的反事实场景：固定机器人任务与障碍几何路径，仅改变相位或速度。它适合验证模型是否真正使用物理时间信息。

## 9. 公平比较：必须统一的协议

### 9.1 目标集合

当前 JointDual 的 EE goal 允许不同关节终态。若 ST-RRT* 只获得一个固定 `q_goal`，两者求解空间不相同。

可选方案：

- **共同 EE 目标协议**：给搜索算法目标区域或共同 IK 候选集合，记录 IK 求解成本；给所有方法一致的任务容限与终端约束。
- **共同固定关节终点协议**：为 JointDual 增加明确的固定关节终点约束，并让所有方法使用同一 `q_goal`。

第一种更贴近当前模型，第二种更容易隔离 timing 能力。若采用离线提供 IK 候选，必须说明求解器是否可访问整个集合、时间成本如何计算，以及所有方法是否具有相同目标自由度。

### 9.2 世界时钟：区分算法评价和在线系统评价

**离线算法协议 B0**：所有规划器从同一 `world_t0` 评估相同未来世界。计算耗时作为求解指标单独计量；世界不因某个求解器计算较慢而在查询内部悄悄改变。这测量给定问题的求解能力。

**在线执行协议 B1/A**：世界在计算期间继续运动；计划起点、启动等待和接管延迟均进入碰撞检查。这测量系统执行能力。

两种协议都合理，但应分表报告。旧 ToDrawer 的 `motion_aligned` 会按模式调整 crossing 时间，可用于交互强度诊断；共享世界下的在线主比较应使用统一绝对时钟。不能为慢算法单独推迟障碍，然后将结果称为同场景在线比较。

### 9.3 后处理和约束

所有方法最终必须通过同一任务级判据：静态碰撞、自碰撞、动态碰撞、关节位置、速度、加速度、目标误差和时间范围。

对搜索方法，允许使用其适当的平滑或动力学后处理，但应计入成本并重新检查物理时间碰撞。对学习方法，也应把 guidance、候选筛选和最终验证计入成本。

不要求所有方法使用完全相同的内部碰撞计算实现，但它们应面对一致几何与 margin，最终由独立于优化网格的公共验证器评价。

速度和加速度限制的满足属于运动学／轨迹约束；如果没有验证力矩与机器人动力学，不应笼统宣称动力学可行。

### 9.4 终端保持与预测覆盖

必须说明机器人到达后是否立即结束占位评价，还是保持目标姿态一段时间。提前到达的轨迹可能在保持期间被移动障碍撞到。

当前世界特征覆盖 14 秒。若评估包含启动等待、接管延迟、轨迹主体和目标保持，总时间必须落在有效预测覆盖范围内；否则需要扩展世界数据或明确拒绝，不能静默外推并仍称为 oracle。

### 9.5 计算资源

分开报告模型加载、预热和稳态规划。主指标包含编码、采样、guidance、验证与后处理；另报各阶段耗时有助于定位优势。

公开 CPU/GPU 型号、线程数、候选数、去噪步数和优化预算。GPU 批量采样是方法优势的一部分，可以保留，但不能将优势全部解释为网络结构改进。

学习方法另报训练数据量、teacher 生成成本和训练成本。在线收益与离线投入是不同维度，不需要把两者强行压缩成一个分数。

## 10. 最小但有解释力的实验矩阵

### 10.1 主基线

| 方法 | 实现范围 | 回答的问题 |
|---|---|---|
| ST-RRT* | 相同障碍时序与目标协议；后处理重验 | 与经典时空搜索相比如何？ |
| SI-RRT | 核对等待和动态碰撞接口 | 与近期机械臂搜索方法相比如何？ |
| 多初值时空优化 | 支持相同物理约束、不同初始化 | 收益是否只是优化初值更好？ |
| 空间扩散＋固定时间 | 在匹配数据条件下训练或明确差异 | 自由时间参数带来多少收益？ |
| 空间扩散＋时间优化 | 空间固定，只优化执行进度和时长 | 联合生成是否优于顺序处理？ |
| 分离的空间／时间模型 | 相同数据、世界信息和近似模型容量 | 联合训练和双向耦合的收益？ |
| JointDual-KIN / WORLD | 相同表示和预算 | 世界条件带来多少收益？ |

不要把仅支持静态障碍的规划器未经适配直接列为动态任务的主基线。可以把“忽略动态障碍”的版本作为诊断下界，但需明确其含义。

### 10.2 消融优先级

| 优先级 | 消融 | 观察指标 |
|---|---|---|
| P0 | 联合模型 vs 匹配的分离模型 | 验证后成功率与预算曲线 |
| P0 | WORLD vs KIN | 原始候选有效率、guidance 成本 |
| P0 | 无 guidance vs 固定预算 guidance | 先验贡献与在线修正贡献 |
| P0 | 固定时间 vs 可变时间 | 到达时间、空间路径选择、碰撞类型 |
| P1 | world phase/speed 反事实 | 条件响应、策略切换 |
| P1 | context 置空、打乱世界与任务配对 | 模型是否依赖正确 context |
| P1 | `c` vs `tau_r` | 解码稳定性、梯度、可行率和耗时 |
| P2 | 候选模式保留与预算重分配 | 同计算量下有效模式数量 |
| P2 | 确定性预测器或非扩散生成器 | 多模态生成是否有额外价值 |

打乱 context 属于诊断输入，可能造成分布偏移，因此其结果只能作为条件依赖证据的一部分，不能单独证明学到了完整物理推理。

### 10.3 指标

- **任务成功率**：完整轨迹通过统一验证且到达目标，分母包含超时和无有效候选。
- **首个可执行解时间**：包含生成、修正和验证；未找到解的运行保留为超时，不从统计中删除。
- **成功率—预算曲线**：预算档位根据硬件校准，例如 0.1、0.25、0.5、1、2 秒；这些数值是建议档位，不是当前已达到的性能。
- **执行质量**：到达时间、关节路径长度、最小 clearance、速度／加速度裕量和 jerk 指标。
- **候选效率**：每请求有效候选比例、首次有效候选前的成本、最终选中轨迹是否来自不同策略。
- **模式覆盖**：围绕指定交互事件标注 before/after/wait/detour；多障碍采用事件序列，而非给整条轨迹强行贴一个标签。
- **失效分类**：静态碰撞、自碰撞、动态碰撞、运动约束、目标误差、时间越界、超时与数值异常。

clearance 依赖碰撞表示。若使用连杆球近似，不能直接解释为精确 mesh 间距离；应报告近似方式和最终验证的覆盖范围。

固定稠密网格检测是数值验证，不等于连续时间无碰撞证明。可采用自适应加密或连续碰撞检测增强证据；如果没有证明，就使用“通过给定验证器”的准确表述。

### 10.4 统计与结果呈现

先用小型开发集排查协议和实现，再冻结测试集。样本量应由预期差异和计算预算确定，不以刚好获得显著性为停止条件。

对同一场景采用配对比较，对随机算法运行多个独立 seed。若同一 family 派生多个 world，置信区间应考虑 family 内相关性，例如使用 family 分组 bootstrap。

执行质量既报告各自成功样本分布，也报告共同成功子集的配对差异，避免“只在容易场景成功”的算法获得看似更短的平均时间。全测试集仍以成功率和预算曲线为主。

建议主文保留四类图：成功率—预算、执行时间—规划预算、耦合强度分组结果、相位反事实的时空轨迹。其余耗时分解和失败类型可以放补充材料。

## 11. 最值得投入的算法改善

### 11.1 优先排除表示和时间语义问题

如果同一 latent 在训练和推理解码时产生不同 duration，或成本计算使用的时刻与最终验证不一致，再复杂的网络也难以可靠工作。

设 `u(s)=dt/ds>0`，则：

\[
\dot q=\frac{q_s}{u},\qquad
\ddot q=\frac{q_{ss}}{u^2}-\frac{q_su_s}{u^3}.
\]

空间参数和时间参数都影响速度与加速度。动态碰撞还依赖障碍在真实时刻的位置。若 `T` 又依赖 `P`，则路径变化也可能通过时间改变碰撞代价。

因此建议先核对：codec round-trip、时间单调性、梯度路径、物理时间查询、最终验证网格和预测覆盖。它们属于建立可信实验的基础，不应单独包装成主要研究贡献。

### 11.2 多模态要体现策略差异

多个候选在关节空间略有不同，不一定代表不同避障策略。更有意义的是是否保留不同通道、不同时间窗口和不同交互顺序。

可以研究按事件序列保留候选，或把后续优化预算分配给不同模式。但这些改进应在固定总候选数与计算预算下验证，避免把多算带来的提升归因于模式方法。

### 11.3 检查表示能否实现等待

真正等待意味着在一个非零时间区间内保持构型不变。时间映射严格单调时，仍可通过空间路径中的常值区间表达等待；但一般平滑拟合未必准确保留这种区间。

当前表示应实测对 teacher 等待段的重建能力。若只能近似慢行，应据实描述；若增加显式等待段或停留变量，需要重新检查拼接连续性、约束和训练标签。

### 11.4 何时才值得升级网络

先区分问题来源：

| 观察 | 更应优先检查 |
|---|---|
| KIN 与 WORLD 相近，反事实也无响应 | context 使用、任务数据配对、条件 shortcut |
| 原始候选差，但 guidance 后接近 | 先验质量、训练目标、teacher 多样性 |
| 解码后就频繁超限或时间错位 | 表示、归一化、codec 与边界 |
| 分离模型同样好 | 场景耦合强度或联合方法是否必要 |
| 小预算有优势，大预算被搜索追上 | 有限预算定位是否仍具有实际价值 |
| OOD 完全失效 | 区分运动模式迁移与静态几何迁移 |

在这些原因尚未明确前，不建议先增加复杂 world encoder、更多辅助 head 或更大的模型。

## 12. 从 B 扩展到 A：分离预测损失与闭环收益

建议在相同真实世界轨迹上逐层增加困难：

| 阶段 | 规划器获得的信息 | 执行方式 | 能回答的问题 |
|---|---|---|---|
| B0 | 完整真实未来 | 离线单次求解 | 算法自身能否找到可行解？ |
| B1 | 完整真实未来 | 世界持续运行，计入启动延迟 | 计算延迟造成多少损失？ |
| A0 | 由无噪声状态产生的有限预测 | 单次执行 | 预测模型失配造成多少损失？ |
| A1 | 同样的有限预测 | 反复重规划 | 闭环修正能挽回多少损失？ |
| A2 | 含观测噪声、丢帧或延迟的预测 | 闭环执行 | 状态估计和时间同步影响多少？ |
| A3 | 真实视觉与跟踪输出 | 真机或传感器闭环 | 感知接口和执行误差是否可接受？ |

不能只比较“oracle 单次”和“有噪声闭环”两个端点，再推断某个模块有效。oracle 与预测输入的差别、单次与重复调用的差别应分别消融。

闭环对照应尽量固定底层规划器，只改变预测、膨胀或切换机制。对不同规划器进行系统对比时，统一控制器、安全执行层和世界信息，并另报各自计算量。

## 13. ROS、算法库与未来视觉模块的边界

以下是建议架构，不代表当前仓库已经完成重构。

**算法库应提供可脱离 ROS 调用的规划与验证核心。** 输入包括任务状态、世界预测、起始物理时刻和预算；输出包括带时间戳的候选、可行性结果及耗时分解。这样 B 类 benchmark 不需要启动完整执行系统。

**共享的闭环决策可以放在独立 Python 模块。** 接管状态预测、候选选择、连接段生成和重验证若成为研究方法，最好形成可单测、可离线回放的组件，避免仅埋在 ROS callback 中。

**ROS 负责在线接入与执行协调。** 相机、目标跟踪、机器人状态、消息时间戳、控制器命令和运行状态保留在运行时边界。无须为了论文先把所有 ROS 逻辑迁入 MPD。

视觉模块接入时，优先保持结构化接口：

```text
视觉 / 检测 / 跟踪
        ↓
带时间戳的障碍状态、几何与预测不确定性
        ↓
统一的世界查询接口与 world context 构造
        ↓
JointDual 生成、guidance、验证
        ↓
接管决策与控制器执行
```

这样接视觉首先改变的是世界信息来源，便于测量感知误差，而无需立即改成图像端到端扩散网络。如果未来确实要研究视觉条件规划，再把视觉编码本身作为独立变量。

当前 WORLD token 没有显式协方差。可以先让均值预测进入网络、风险信息进入碰撞或筛选层；如果声称模型学到了不确定性下的策略选择，则需要提供相应输入、训练分布与消融，不能只依赖外部膨胀。

## 14. 分阶段工作与继续条件

| 阶段 | 交付物 | 继续投入的条件 |
|---|---|---|
| 1. 协议与实现核对 | 固定世界集、目标协议、公共验证器、可重复 runner | 同请求可复现，时间与约束语义一致 |
| 2. 最小算法实验 | JointDual、匹配分离模型、ST-RRT*、SI-RRT 的预算曲线 | 原始及验证后结果可信，失败原因可解释 |
| 3. 贡献检验 | context、guidance、时间自由度与联合结构消融 | 至少一个核心假设得到稳定支持 |
| 4. 泛化与场景扩展 | 运动模式 OOD、ToDrawer 或其他静态场景 | 能区分算法能力与分布迁移限制 |
| 5. 闭环扩展 | 非零初速度接管、预测误差、延迟与噪声实验 | 连接段与新轨迹统一验证，执行日志完整 |
| 6. 真机验证 | 受控动态障碍，随后视觉跟踪输入 | 仿真问题已可解释，真实时钟和控制接口经过核对 |

建议在第 3 阶段作研究方向判断：如果联合模型不能稳定优于公平配置的分离模型，先检查数据和耦合任务是否足够，再决定改表示或调整贡献定位。不要用更复杂的 ROS 演示掩盖核心算法对照不足。

对于单次规划论文，真机可以先使用轨迹已知的移动平台、可控障碍或另一台机械臂，验证规划输出可执行。真实感知不确定性是下一层问题，不必一次承担所有研究范围。

## 15. 投稿主张与证据边界

| 可以考虑的主张 | 必须具备的证据 | 暂时不应扩张成的主张 |
|---|---|---|
| 联合生成提高有限预算成功率 | 匹配分离基线、多个任务家族与随机种子 | 联合方法在所有动态场景都更优 |
| world context 改善动态条件适应 | 相位／速度反事实、context 消融 | 已具备未知场景全面泛化 |
| 生成轨迹可执行 | 公共约束验证与执行实验 | 任意连续时间、任意预测误差下安全 |
| 预测闭环改善完成率 | 同世界、同预算的单次与闭环对照 | 无条件递归可行或概率安全 |
| 支持 ToDrawer 迁移 | 明确零样本、微调或重训协议 | 单一静态环境训练即可适应所有家具 |

更稳妥的论文结构是：问题与动机、联合表示和模型、物理时空 guidance、确定性主实验、机制消融、预测与执行扩展、限制。benchmark 可以成为可复现贡献，但随机障碍数量增加或发布场景文件本身不应承担全部新颖性。

是否具有足够投稿竞争力，最终取决于主假设是否成立、对照是否公平、改进是否具有实际量级。当前建议首先投资于能回答这些问题的 B 类实验，再决定 A 应承担演示、补充实验还是下一篇方法工作的角色。
