可以，而且你的思路是正确方向：先粗采样进行 broad phase，根据 SDF、自碰撞间隙和运动幅度选择危险区间，再只在危险区间稠密采样、计算 Jacobian 和梯度。最终平均采样点数可以明显少于 128。
推荐的两阶段流程
第一阶段：粗筛选
例如从 128 个预计算 B 样条点中均匀选 16 或 32 个：
\[
q_k=B_k w
\]粗筛阶段只计算：
B 样条关节位置。
FK 和碰撞球位置。
SDF 距离。
自碰撞球对距离。
关节限制距离。
暂时不计算昂贵的 Jacobian。
对障碍物定义余量：
\[
c_{m,k}=sdf(x_{m,k})-r_m-\epsilon
\]对自碰撞定义：
\[
c_{ij,k}
=
\|x_{i,k}-x_{j,k}\|-r_i-r_j
\]若粗采样点满足：
SDF clearance 很大
自碰撞 clearance 很大
关节距离 limit 很远
相邻 q 变化和曲率较小
则该区间保持稀疏。
第二阶段：危险区间细化
以下情况对区间二分或加入 2～4 个采样点：
任一球 SDF clearance < refine_margin。
任一自碰撞 pair 间隙小。
区间两端 SDF 差异大。
\(\|q_{k+1}-q_k\|\) 大。
B 样条曲率大。
粗采样点已经碰撞。
最终可能变成：
安全轨迹：16～32 点
一般轨迹：32～64 点
危险轨迹：64～128 点
最后仍使用 128～256 点做一次无梯度碰撞验证；若失败则丢弃或再进行一次稠密修正。
如何避免粗采样漏碰撞
仅看区间端点不安全。SDF 是 1-Lipschitz：
\[
|sdf(x_1)-sdf(x_2)|\leq\|x_1-x_2\|
\]因此可以使用保守判据。若：
\[
\min(c_k,c_{k+1})
>
\Delta x_{\max}
\]其中 \(\Delta x_{\max}\) 是区间内碰撞球最大可能移动距离，则可以认为该区间安全。
实际可近似用：
\[
\Delta x_{\max}
\approx
\|J(q)\|\,\|q_{k+1}-q_k\|
\]没有这个运动上界时，自适应采样只能作为启发式，最终必须做稠密验证。
应先算 FK，还是 FK+Jacobian

100 条轨迹 × 128 点 × 56 个碰撞球

EE goal 只算最后一个轨迹点。

粗采样只算 FK，不算 Jacobian。

自碰撞先做 14 个 link-pair broad phase，再展开 548 个球对。

用 8 个父 link FK 替代 56 个虚拟球 link FK。

最后加入自适应时间采样。

自适应采样虽然理论收益大，但会产生不同轨迹不同采样数量，不利于 GPU batch。工程上建议：

每条轨迹从中选 top-K 危险索引。
按 K=16/32/64/128 分桶 batch。

最终统一做 128 点验证。
这样通常比完全动态递归采样更容易在 GPU 上取得真实加速。

方向 1：梯度计算减枝
最值得做的不是“固定从 128 个点减到 32 个点”，而是分层计算：
控制点
  → 16/32 个粗采样点，只做 FK/SDF 距离
  → 找出危险时间区间、危险球、危险自碰撞 link pair
  → 只对 active set 计算 Jacobian
  → 对危险区间加密到 64/128 点
  → 最终用 256/512 点独立碰撞验证
可以分四级实现：
时间减枝：根据粗采样 SDF、关节变化量、轨迹曲率决定哪些 B 样条区间需要加密。
碰撞球减枝：先用 link bounding sphere/capsule 检查，只有接近障碍物的 link 才展开详细球。
自碰撞 pair 减枝：先计算 link-level 距离，再展开当前约 548 个 sphere pair。
Jacobian 减枝：距离查询只需要 FK；只有 distance < activation_margin 的点才需要 Jacobian。
这里最关键的是第四项。仅在算完所有 Jacobian 后 mask，通常不会显著加速。
相关工作包括：
cuRobo, arXiv:2310.17274：GPU 并行多 seed 优化，约 50 ms 规划，是必须对比的速度基线。
DiffCo, arXiv:2102.07413：可在线更新的可微碰撞代理，报告比几何检查快 10–100 倍。
RAMP, arXiv:2305.10534：用 configuration-space implicit SDF 做反应式重规划。
Neural Implicit Swept Volume, arXiv:2402.15281：连续 swept-volume 神经距离模型，并保留几何 checker。
nvblox, arXiv:2311.00626：适合从深度相机实时更新 ESDF，但它解决的是地图更新，不会自动解决机器人 FK/Jacobian 和自碰撞耗时。
创新性判断：
固定降采样、简单 threshold mask：约 2/5。
B 样条区间风险估计 + active Jacobian + link/sphere/pair 分层减枝：约 3.5/5。
再加入基于 B 样条导数和 SDF Lipschitz 性质的保守误差界：约 4/5。
如果没有误差界，最终 dense checking 能保证“输出轨迹经过验证”，但不能保证优化过程中没有漏掉本应产生梯度的碰撞区间。

可以，而且这通常比直接在当前带噪控制点 \(x_t\) 上计算 cost 更合理。这个方法本质上是：
当前 diffusion step 先预测 clean control points \(\hat x_0\)，将其展开为完整 B 样条轨迹，在这条“预测最终轨迹”上计算 cost 和梯度，再用梯度修正本次 DDIM 更新。

1. 当前做法和建议做法
当前大致是：
当前带噪控制点 x_t
    ↓
CostGuide(x_t)
    ↓
修改 denoising noise / score
    ↓
得到 x_{t-1}
建议尝试：
当前带噪控制点 x_t
    ↓ denoiser
预测 clean control points x0_hat
    ↓ B-spline
预测最终 waypoint 轨迹
    ↓
FK / SDF / self-collision / joint limits
    ↓
grad C(x0_hat)
    ↓
修正 x0_hat
    ↓ DDIM update
得到 x_{t-1}
数学上：
\[
\hat x_0
=
\frac{x_t-\sqrt{1-\bar\alpha_t}\epsilon_\theta(x_t,t)}
{\sqrt{\bar\alpha_t}}
\]然后计算：
\[
g_0=\nabla_{\hat x_0}C(\hat x_0)
\]修正预测的最终控制点：
\[
\hat x_0^{guided}
=
\hat x_0-\eta_t g_0
\]最后由修正后的 \(\hat x_0^{guided}\) 生成 \(x_{t-1}\)。
2. 为什么可能比当前方法更有效
碰撞梯度更有物理意义
当前 \(x_t\) 包含 diffusion noise。将它展开成 waypoint 后：
关节角可能不自然；
B 样条可能穿过大量障碍物；
FK/SDF 梯度可能非常大；
梯度方向可能只是在修复噪声，而不是修复最终轨迹。
而 \(\hat x_0\) 是模型认为的最终 clean trajectory，因此：

尤其当前 guidance 只在最后约 5/15 个 DDIM step 开启，这时 \(\hat x_0\) 已经通常具有明确轨迹形状，很适合进行 clean-trajectory guidance。
可以减少重复 cost guide
当前配置大致是：
\[
5\text{ 个 active DDIM step}
\times
6\text{ 个 guide step}
=

\]而且同一个 DDIM step 内，denoiser model_out 并没有重新计算，只有轨迹不断被 guide 修改。因此后几次 cost gradient 是在“已经变化的轨迹 + 旧 denoiser 输出”上工作。

方式 A：直接修正预测的 \(\hat x_0\)  方式 B：将 \(\hat x_0\) 的梯度映射回 \(x_t\) 具体解释一下


两者的共同起点都是：不在带噪的 \(x_t\) 上解释碰撞，而是先让 denoiser 预测最终干净轨迹 \(\hat x_0\)，在 \(\hat x_0\) 上计算真实几何 cost。
区别在于梯度最终作用在哪里：
方式 A：把 \(\hat x_0\) 当作可以直接优化的轨迹变量。
方式 B：把 cost 看成关于 \(x_t\) 的复合函数，通过 denoiser Jacobian 将梯度传回 \(x_t\)。
1. 基础关系
扩散前向过程为：
\[
x_t=\sqrt{\bar\alpha_t}x_0+\sqrt{1-\bar\alpha_t}\epsilon
\]记：
\[
a_t=\sqrt{\bar\alpha_t},\qquad
b_t=\sqrt{1-\bar\alpha_t}
\]网络预测噪声：
\[
\epsilon_\theta=\epsilon_\theta(x_t,t,c)
\]预测最终干净控制点：
\[
\hat x_0
=
\frac{x_t-b_t\epsilon_\theta(x_t,t,c)}{a_t}
\]这里的 \(\hat x_0\) 是归一化 B 样条控制点。CostGuide 将其展开为 waypoint：
\[
q=B\hat x_0
\]再计算：
\[
C(\hat x_0)
=
C_{\mathrm{collision}}
+C_{\mathrm{self}}
+C_{\mathrm{joint}}
+C_{\mathrm{goal}}
+\cdots
\]得到：
\[
g_0=\nabla_{\hat x_0}C(\hat x_0)
\]两种方式从这里开始分开。
方式 A：直接修正 \(\hat x_0\)
2. 基本形式
直接执行控制点空间的梯度下降：
\[
\hat x_0^{\,g}
=
\hat x_0-\eta_t g_0
\]然后把修正后的 clean trajectory 放回 DDIM 更新：
\[
x_{t-1}
=
a_{t-1}\hat x_0^{\,g}
+
c_t\epsilon_\theta
+
\sigma_tz
\]其中 \(c_t\) 是 DDIM 中保留噪声方向的系数。
计算流程是：
x_t
 ↓ denoiser forward
epsilon_theta
 ↓ predict_start_from_noise
x0_hat
 ↓ CostGuide
grad C(x0_hat)
 ↓ gradient descent
x0_hat_guided
 ↓ DDIM update
x_{t-1}
3. 它优化的是什么
方式 A 直接认为：
既然模型已经给出了大致的最终 B 样条，就直接对这条最终轨迹做一次 trajectory optimization。

这和传统轨迹优化很接近，只不过每个 diffusion step 都会重新生成一个新的预测最终轨迹。
例如 collision cost：
\[
C_{\mathrm{obs}}
=
\frac12
\sum_{i,l}
\operatorname{ReLU}
(r_l+m-d(p_{i,l}))^2
\]先得到 waypoint 关节梯度：
\[
\nabla_{q_i}C
=
J_i^T\nabla_{p_i}C
\]再映射到 B 样条控制点：
\[
g_0
=
\nabla_{\hat x_0}C
=
B^T\nabla_qC
\]然后直接修改控制点：
\[
\Delta\hat x_0=-\eta_tB^TJ^T\nabla_pC
\]这里不经过 diffusion 网络的 Jacobian。
4. 修正后如何处理噪声
有两种选择。
A1. 保留原始预测噪声
\[
x_{t-1}
=
a_{t-1}\hat x_0^{\,g}
+
c_t\epsilon_\theta
\]这表示：
clean trajectory 被 cost 修正；
diffusion prior 给出的噪声方向仍保留；
实现简单；
通常更稳定。
建议第一版使用这种方式。
A2. 重新计算一致噪声
根据当前 \(x_t\) 和修正后的 \(\hat x_0^{\,g}\)：
\[
\epsilon^{g}
=
\frac{x_t-a_t\hat x_0^{\,g}}{b_t}
\]再用 \(\epsilon^g\) 做 DDIM 更新。
它能让三者严格满足：
\[
x_t=a_t\hat x_0^{\,g}+b_t\epsilon^g
\]但 cost 修正也会改变噪声方向，有时修正会被部分抵消或放大。建议作为消融实验，不作为第一版默认实现。
5. 方式 A 的优缺点
优点：
不需要对 UNet 反向传播；
只需要当前 CostGuide 已有的控制点梯度；
显存增加很小；
适合减少 n_guide_steps；
物理意义清楚；
很适合最后几个低噪声 DDIM step。
缺点：
强行修改 \(\hat x_0\)，可能离开模型数据分布；
没考虑 denoiser 对不同控制点方向的敏感程度；
早期 \(\hat x_0\) 不可靠时，梯度可能推动错误路径；
大步长可能破坏轨迹模态和多样性。
因此需要 trust region：
\[
\Delta x_0
=
\operatorname{clip}(-\eta_tg_0,-\delta_t,\delta_t)
\]以及：
\[
\hat x_0^{\,g}
=
\operatorname{clip}(\hat x_0+\Delta x_0,-1,1)
\]最后重新应用 start/goal hard conditioning。
方式 B：将梯度映射回 \(x_t\)
6. 复合函数形式
方式 B 不直接修改 \(\hat x_0\)，而是定义：
\[
L_t(x_t)
=
C(\hat x_0(x_t,t))
\]因为 \(\hat x_0\) 是 \(x_t\) 经过 denoiser 得到的，所以：
\[
\nabla_{x_t}L_t
=
\left(
\frac{\partial\hat x_0}{\partial x_t}
\right)^T
\nabla_{\hat x_0}C
\]记：
\[
g_t=\nabla_{x_t}L_t
\]然后在带噪变量空间更新：
\[
x_t^{\,g}=x_t-\lambda_tg_t
\]之后再从 \(x_t^{\,g}\) 执行下一步去噪。
流程是：
x_t
 ↓ denoiser forward，并保留计算图
epsilon_theta
 ↓
x0_hat
 ↓ CostGuide
g_0 = grad C(x0_hat)
 ↓ denoiser vector-Jacobian product
g_t = (dx0_hat/dx_t)^T g_0
 ↓
修改 x_t 或 diffusion score
 ↓
x_{t-1}
7. denoiser Jacobian 是什么
由：
\[
\hat x_0
=
\frac{x_t-b_t\epsilon_\theta(x_t,t,c)}{a_t}
\]可得：
\[
\frac{\partial\hat x_0}{\partial x_t}
=
\frac{1}{a_t}
\left(
I-b_t
\frac{\partial\epsilon_\theta}{\partial x_t}
\right)
\]所以：
\[
g_t
=
\frac{1}{a_t}
\left(
I-b_tJ_\epsilon
\right)^Tg_0
\]其中：
\[
J_\epsilon
=
\frac{\partial\epsilon_\theta}{\partial x_t}
\]直观上，\(J_\epsilon\) 描述：
改变当前带噪控制点 \(x_t\) 后，denoiser 预测的最终轨迹会怎样改变。

因此方式 B 会考虑模型本身对梯度方向的响应。
8. 不需要显式构造完整 Jacobian
不能直接构造：
\[
J_\epsilon\in\mathbb{R}^{D\times D}
\]而应该使用 vector-Jacobian product：
x_t.requires_grad_(True)

eps = model(x_t, t, context)
x0_hat = predict_start_from_noise(x_t, t, eps)

g0 = guide(x0_hat.detach())

g_t = torch.autograd.grad(
    outputs=x0_hat,
    inputs=x_t,
    grad_outputs=g0,
)[0]
这里 g0 可以继续由当前手写 CostGuide 计算，不要求 FK/SDF 全部改成 PyTorch autograd。
这只是一次通过 denoiser 的反向传播，不是二阶梯度；但它的时间和显存通常接近一次网络训练 backward。
9. 得到 \(g_t\) 后如何使用
B1. 直接修改 \(x_t\)
\[
x_t^{\,g}
=
x_t-\lambda_tg_t
\]为了严格一致，修改后最好重新运行：
\[
\epsilon_\theta(x_t^{\,g},t,c)
\]这意味着每个 guide step 多一次 denoiser forward，并且之前还有一次 backward，代价较高。
如果不重新 forward，使用旧的 \(\epsilon_\theta\)，则是近似更新。
B2. 修改 diffusion score/noise
目标后验可以写成：
\[
p(x_t\mid\text{constraints})
\propto
p_\theta(x_t)\exp(-\lambda C)
\]因此后验 score 为：
\[
\nabla_{x_t}\log p
=
\nabla_{x_t}\log p_\theta
-\lambda g_t
\]因为噪声预测和 score 的关系约为：
\[
s_\theta(x_t,t)
=
-\frac{\epsilon_\theta}{b_t}
\]所以可以将 cost gradient 转换成 guided noise，再完成 DDIM 更新。
具体正负号必须和当前 guide() 返回的是“cost gradient”还是“descent direction”统一，不能直接照搬当前 grad_prior - grad_guide 的符号。
10. 忽略 denoiser Jacobian的近似
为了避免 UNet backward，可以令：
\[
\frac{\partial\epsilon_\theta}{\partial x_t}\approx0
\]得到：
\[
g_t
\approx
\frac{1}{a_t}g_0
=
\frac{1}{\sqrt{\bar\alpha_t}}g_0
\]这就是 stop-gradient 近似。
问题是早期：
\[
\bar\alpha_t\ll1
\]所以：
\[
\frac{1}{\sqrt{\bar\alpha_t}}
\]可能很大，导致梯度爆炸。
但在最后几个 diffusion step：
\[
\bar\alpha_t\approx1
\]于是：
\[
g_t\approx g_0
\]这说明：如果 guidance 只发生在最后几个 step，方式 A 和 stop-gradient 方式 B 实际会比较接近。
两种方式的本质差别
考虑一维例子：
\[
\hat x_0=f(x_t)
\]\[
C=\frac12(\hat x_0-y)^2
\]则：
\[
g_0=\hat x_0-y
\]方式 A：
\[
\hat x_0^{\,g}
=
\hat x_0-\eta(\hat x_0-y)
\]它直接把预测结果推向 \(y\)。
方式 B：
\[
x_t^{\,g}
=
x_t-\lambda f'(x_t)(\hat x_0-y)
\]如果：
\[
|f'(x_t)|\ll1
\]说明 denoiser 对这个输入方向不敏感。方式 B 会减少该方向上的更新，而方式 A 仍然强行修改最终输出。
因此：
方式 A：更像外部轨迹优化器。
方式 B：更像在 diffusion 概率模型内部做后验采样。

L(\tau_t)
=
J\big(\hat\tau_0(\tau_t)\big)
\]因此梯度应为：
\[
\nabla_{\tau_t}L
=
\left(
\frac{\partial\hat\tau_0}{\partial\tau_t}
\right)^T
\nabla_{\hat\tau_0}J
\]也就是：
\[
\tau_t
\leftarrow
\tau_t
-w
\nabla_{\tau_t}
J\big(\hat\tau_0(\tau_t)\big)
\]由于：
\[
\hat\tau_0
=
\frac{
\tau_t-\sqrt{1-\alpha_t}\epsilon_\theta(\tau_t)
}{
\sqrt{\alpha_t}
}
\]所以：
\[
\frac{\partial\hat\tau_0}{\partial\tau_t}
=
\frac{1}{\sqrt{\alpha_t}}
\left[
I-
\sqrt{1-\alpha_t}
\frac{\partial\epsilon_\theta}{\partial\tau_t}
\right]
\]最终：
\[
\nabla_{\tau_t}J
=
\frac{1}{\sqrt{\alpha_t}}
\left[
I-
\sqrt{1-\alpha_t}J_{\epsilon}
\right]^T
\nabla_{\hat\tau_0}J
\]这就是完整的方式 B，需要通过 denoiser 做一次 vector-Jacobian product。
为什么认为作者意图是方式 B
主要有三个证据。
1. 更新变量明确写的是 \(\tau_t\)
Algorithm 1 第 18 行：
\[
\tau_t^{(k)}
\leftarrow
\tau_t^{(k)}
-w\nabla J(\hat\tau_0^{(k)})
\]不是修改 \(\hat\tau_0\)。
2. 修改后重新进行 denoising
第 19 行：
\[
\tau_{t-1}^{(k)}
\sim
p_\theta(\tau_{t-1}\mid\tau_t)
\]说明 cost guidance 是对当前 diffusion state 进行修正，然后继续正常反向扩散。
3. 引用了 Diffusion Posterior Sampling
其公式 (3) 附近引用了：
Diffusion Posterior Sampling，arXiv:2209.14687；
Tweedie’s formula。
DPS 的标准做法正是：
\[
\nabla_{x_t}
C(\hat x_0(x_t))
\]也就是通过预测 clean sample 将观测或 cost 梯度反传到当前 noisy sample。
因此从方法意图和引用关系看，应将它归类为方式 B。
论文没有说明清楚的地方
公式 (7) 只写：
\[
\nabla J(\hat\tau_0)
\]没有写：
\[
\nabla_{\tau_t}J(\hat\tau_0(\tau_t))
\]还是：
\[
\nabla_{\hat\tau_0}J(\hat\tau_0)
\]这在数学上是不完整的。可能有三种实际实现。
B-full：完整反传
tau_t.requires_grad_(True)

eps = model(tau_t, t)
tau_0_hat = predict_x0(tau_t, eps, t)
cost = collision_cost(tau_0_hat)

grad_tau_t = torch.autograd.grad(cost.sum(), tau_t)[0]
tau_t = tau_t - w * grad_tau_t
这是真正的方式 B，并包含：
\[
\frac{\partial\epsilon_\theta}{\partial\tau_t}
\]计算成本包括一次 UNet backward。
B-stopgrad：忽略 denoiser Jacobian
如果将网络预测的噪声 detach：
eps = model(tau_t, t).detach()
tau_0_hat = predict_x0(tau_t, eps, t)
cost = collision_cost(tau_0_hat)

grad_tau_t = torch.autograd.grad(cost.sum(), tau_t)[0]
则：
\[
\nabla_{\tau_t}J
\approx
\frac{1}{\sqrt{\alpha_t}}
\nabla_{\hat\tau_0}J
\]仍然属于方式 B 的近似版本，但不经过 UNet backward，速度更快。
Identity：直接拿 \(\hat\tau_0\) 梯度更新 \(\tau_t\)
也可能实现为：
grad_x0 = gradient_collision_cost(tau_0_hat)
tau_t = tau_t - w * grad_x0
这实际是假设：
\[
\frac{\partial\hat\tau_0}{\partial\tau_t}\approx I
\]它既不是严格的方式 A，也不是完整的方式 B，而是“在 clean trajectory 算梯度、直接施加到 noisy trajectory”的启发式近似。
仅从 PDF 无法排除这一实现，因为论文没有给代码，也没有说明是否保留 denoiser autograd graph。
与当前 MPD 的区别
论文处理的是 50 个 waypoint：
\[
\tau\in\mathbb R^{50\times7}
\]而当前项目扩散的是 B 样条控制点：
\[
x\in\mathbb R^{N_{\mathrm{cp}}\times7}
\]如果在当前项目中复现论文思路，链路应当是：
\[
x_t
\rightarrow
\hat x_0
\rightarrow
q=B\hat x_0
\rightarrow
\text{FK/SDF}
\rightarrow
J
\]完整梯度为：
\[
\nabla_{x_t}J
=
\left(
\frac{\partial\hat x_0}{\partial x_t}
\right)^T
B^T
J_{\mathrm{FK}}^T
\nabla_pJ
\]当前 CostGuide 已经可以提供：
\[
g_0
=
\nabla_{\hat x_0}J
=
B^TJ_{\mathrm{FK}}^T\nabla_pJ
\]所以只缺：
\[
g_t
=
\left(
\frac{\partial\hat x_0}{\partial x_t}
\right)^Tg_0
\]这一层 denoiser VJP。
论文的效果
论文 Table III 比较了：
Guidance 计算轨迹	Global	Both	Hybrid
当前 noisy 轨迹 \(\tau_t\)	89.44%	91.44%	91.94%
预测最终轨迹 \(\hat\tau_0\)	94.22%	96.88%	96.66%

在预测最终轨迹上计算 cost，成功率提高约 5 个百分点。这支持“clean trajectory guidance”确实比直接对 noisy trajectory 算碰撞更准确。
但它使用：
256 个 diffusion step；
500 条并行候选；
AABB swept/intersection volume cost；
50 个 waypoint。
论文没有报告完整推理延迟，因此它证明的是成功率改善，不等于证明了实时性。
结论
最准确的分类是：
这篇论文在 \(\hat\tau_0\) 上评价 cost，但修改的是当前 \(\tau_t\)，方法意图属于方式 B，即 \(\nabla_{\tau_t}J(\hat\tau_0(\tau_t))\)。

不过 PDF 没有明确说明是否完整保留 denoiser Jacobian。没有代码的情况下，无法确认它使用的是：
完整 B：通过 UNet 反传；
stop-gradient B：忽略 UNet Jacobian；
identity 近似：直接把 \(\hat\tau_0\) 梯度施加到 \(\tau_t\)。
对当前项目，建议优先实现 B-stopgrad 和方式 A，再把完整 B-full 作为消融；因为 B-full 的 UNet backward 很可能增加推理时间，而当前目标是实时规划。


2026-08-03 当前仓库实现更新

1. clean-x0 已采用方式 A1。
denoiser 在当前 DDIM step 产生原始 epsilon_theta 和 detached x0_hat；CostGuide 只直接修正 x0_hat。构造 x_(t-1) 时保留本轮原始 epsilon_theta，不通过 UNet 反向传播，也不根据 guided x0 重新计算一致噪声。对于直接预测 x0 的模型，先从未修改的 x0_hat 推导一次等价原始 epsilon，再在整个 guide iteration 内保持它不变。

2. 同一 DDIM step 复用 Temporal selection。
guide_iteration=0 执行 coarse FK/SDF/self-collision 扫描；同一 context、diffusion timestep、batch/horizon、device/dtype 下的后续 guide iteration 复用 active selection。下一 DDIM step或缓存键变化会重新扫描。默认开关为：

gradient_pruning.temporal.reuse_selection_within_ddim_step: true

3. selector 已改为 GPU 批量分桶。
risk count、K0/K32/K64/K128 分配、风险点优先保留、均匀 phase 补点均使用批量 GPU 张量运算。active indices 保存为 packed [B,H] 矩阵，Jacobian 分桶直接读取该矩阵，不再对每条候选执行 Python bool/nonzero/isin/unique。

4. 小规模 CUDA smoke。
Warehouse open-clearance、1 context、4 candidates、1 repeat 中，selection cache hit 为 9/12；A3R guide 从修改前匹配 smoke 的 0.175 s 降为 0.167 s，valid 均为 100%。该结果只验证实现方向，不替代正式多场景重复计时，Temporal 继续默认关闭。

5. clean-x0 已直接接在 A2P-fast 后面。
消融配置关闭 Temporal，保留 parent-link 和 dense parent fast path。4 guide steps 的 guide 时间为 0.117 s，与 A2P-fast 的 0.118 s 基本持平，但 valid 从 4/4 降为 3/4。2 guide steps 的 guide/inference 为 0.067/0.124 s，valid 为 4/4，但 EE position/orientation mean 从 0.0134/1.295 回退到 0.0308/4.376，smoothness mean 从 38.23 增至 98.13。说明结构可行，但当前 clean-space 步长和 trust region 不适合生产启用。

6. CostGuide 显式梯度链与 B-spline 映射更新。
Legacy/Pruned guide 均在 no_grad 下执行；Velocity、Acceleration、PathLength 已改为解析梯度，零权重 cost 直接跳过。Pruned B-spline 默认将 basis 映射与 trapezoid 积分融合为一次 [B,H,D] 到 [B,K,D] contraction；设置 gradient_pruning.mapping.fused_bspline_integration: false 可回退原 [B,H,K,D] 物化路径。最终有效性筛选统一为 128 点，runtime/benchmark 不再使用不同点数。
