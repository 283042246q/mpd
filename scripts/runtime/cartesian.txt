 ### 当前 IK 怎么算

  笛卡尔输入时，补丁执行：

  1. 将 [x,y,z,qx,qy,qz,qw] 转成齐次变换矩阵。
  2. 生成 64 个 IK 初值：
      - 大部分在当前 q_start 周围加入标准差 0.6 rad 的扰动；
      - 16 个在关节范围内均匀随机；
      - 第一个初值就是 q_start。

  3. 调用 Torch Robotics 的可微 IK：
      - 最多 600 次迭代
      - 学习率 0.05

  4. 筛选：
      - 位置误差 ≤ 15 mm
      - 姿态误差 ≤ 3°
      - 在规划后端关节范围内
      - 在 Warehouse 场景中无碰撞

  5. 对有效解按“离起点距离 + 位姿误差”评分，选择一个 IK 解。

  实现位于 MotionPlanningDiffusion/mpd/scripts/runtime/infer_once.py:409。

  ### 为什么当前模型不依赖 q_pos_goal

  当前模型同时配置了：

  context_qs: true
  context_ee_goal_pose: true

  见 MotionPlanningDiffusion/mpd/data_trained_models/launch_train_diffusion_models-v04_2024-09-18_08-12-54/
  generative_model_class___GaussianDiffusionModel/dataset_subdir___EnvWarehouse-RobotPanda-config_file_v01-
  joint_joint-one-RRTConnect/dataset_file_merged___dataset_merged_doubled.hdf5/context_ee_goal_pose___True/
  unet_input_dim___32/unet_dim_mults_option___1/context_q_out_dim___128/context_ee_goal_pose_out_dim___128/
  context_combined_out_dim___128/bspline_num_control_points_desired___18/
  parametric_trajectory_class___ParametricTrajectoryBspline/0/args.yaml:7。

  这种组合下，模型的关节 context 只有：

  context_qs = q_start

  不是：

  context_qs = [q_start, q_goal]

  见 MotionPlanningDiffusion/mpd/mpd/datasets/trajectories_dataset_bspline.py:314。

  同时，由于 context_ee_goal_pose=true：

  - B-spline 最后一个关节控制点由扩散模型预测；
  - 末端不会被强制固定成传入的 q_pos_goal；
  - EE position/orientation guide 把最后时刻推向目标笛卡尔位姿；
  - best trajectory 也是按末端笛卡尔误差等指标选择。

  因此当前实际条件可以概括为：

  扩散模型条件 = 当前 q_start + 目标 EE pose
  优化目标      = 碰撞、关节限制、平滑度、目标 EE pose
  最终 q_goal   = 模型自己找到的一个 IK 分支

  ### 那能不能“不输入或随便输入”？

  外部笛卡尔接口：确实不需要输入 q_pos_goal，现在也已经禁止同时输入。

  内部 plan_trajectory()：旧 API 仍要求传一个 [7] 的 q_pos_goal 张量，见 MotionPlanningDiffusion/mpd/mpd/
  inference/inference.py:594。对于当前配置，如果传入另一个合法有限的关节状态，在固定随机种子的情况下，核心 MPD
  输出理论上应基本不受它影响。

  但不建议“随便输入”，原因是：

  - 非法形状、NaN、超限或碰撞状态可能触发外围检查；
  - 换成 gp_prior、knn_prior、RRTConnect 或其他 checkpoint 后，q_pos_goal 可能会真正参与规划；
  - 关节输入模式中，q_pos_goal 会先通过 FK 定义目标笛卡尔位姿，当然不能随便填。

  ### 当前 IK 的真实作用

  严格来说，我之前将它描述成“扩散模型的关节目标 condition”不够准确。对当前 checkpoint，它主要是：

  - 目标可达性预检查；
  - 寻找至少一个满足误差和碰撞条件的 IK；
  - 给旧 plan_trajectory(q_start, q_goal, ee_goal) API 提供合理占位值；
  - 为未来可能使用 q_goal 的 planner/checkpoint 保持兼容。

  如果只针对当前 MPD 配置，可以进一步简化为：

  q_pos_goal_placeholder = q_pos_start

  然后完全依靠 EE pose context 和 guide 做规划。但这样会失去规划前的 IK 可达性与目标碰撞检查。更合理的处理是保留
  IK，但把变量和文档称为 validated_ik_reference，明确它是“验证/兼容参考”，不是当前扩散模型真正的 goal context。
